# aiteam-lab：Agent 集群斗蛐蛐实验室

> 用 [aiteam-frame](https://github.com/HoldenXiee/aiteam-frame)（一个 agent 操控库）搭对照实验台，
> 客观测量一个问题：**多 agent 集群 vs 固定流程 vs 单 agent，到底谁该在什么时候用？**

这不是又一篇"我们提出了一个框架"的仓库。这里没有新框架，只有**对照实验和客观数据**——
所有结论都由本地重算的判分器裁决，不信任任何 LLM 的自我报告。

## 研究问题

1. **自由编排 vs 固定流程，边界在哪？**（哪些任务形状下前者真的赢，哪些必输？）
2. **上下文隔离 vs 共享，边界在哪？**（每个 agent 独立上下文 vs 共享黑板，分别在什么条件下更优？）

## 实验台设计

- **被试**：aiteam-frame 上的两种编排——
  - `fixed`：固定流程。按 REALM-Bench 论文 notebook 里手写的角色分工（如"场地设置→路线规划→时间窗校验→执行"）拓扑序执行；
  - `free`：自由集群。一个 lead agent 拿着花名册自主决定拆不拆、开几个分身、怎么分工。
- **裁判**：不信任自报。三个任务族各有客观判分器——
  - T3：钉死的 Job-Shop 调度实例，离线穷举 1680 个序列得**精确最优 makespan**，产出逐行核验；
  - T4b：数据依赖链，12 个数字字段本地重算逐字段核对；
  - T4：5 条机器可核验约束过 4 次角色交接，测**逐跳存活曲线**。
- **对照变量**：上下文策略三档（全隔离 / 读共享写隔离 / 全共享黑板）、编排宽度（forceSpawn）、模型（3 个厂家）。

## 主要发现（截至 2026-10-03）

### 1. 纯规划任务上，自由集群全胜，而且大多选择"单干"

P1–P10 十个规划任务、三个不同厂家的模型：自由集群目标达成率 100%（固定流程均值 78%），
成本低 5–7 倍。更关键的是**编排决策的涌现**：简单任务上 lead 全部选择单干（1 次调用），
复杂任务（灾害救援、供应链）自发开 2–3 个分身——没人教过它。

### 2. 固定流程的失败不是"模型不行"，是结构性的

三种可复现的失败机制，全部在链条里产生：
- **场景漂移**：中间角色编造了任务里不存在的实体，链条忠实传递到底；
- **身份丢失**：钉死的工序 ID 跨 5 跳改名成匿名序号，不可追溯；
- **约束蒸发**：5 条给定约束过 4 次交接，第一跳丢 60%，终稿只剩 20%（自由集群同任务 100% 存活）。

### 3. 自报达成不可信——三次被客观判分器当场证伪

机械判分（自报 goal 匹配）给固定流程的 5 个 100%，被盲评和客观判分打回 2–3 分；
一次自由集群运行自报"makespan 已达成"，判分器发现它 0/9 工序可识别（解的是自己编造的题）。
**结论：任何 LLM 多 agent 实验都必须配机器判分，"自报 + LLM 裁判"存在循环论证。**

### 4. 规模过渡带在 3→6 之间——而单上下文自身毫无压力

| 数据链规模 | 多 agent 集群 | 单次调用（同模型同数据） |
|---|---|---|
| 3 部件（12 字段） | 三种上下文策略全部 12/12 | 12/12 |
| 6 部件 | 编排塌缩：分身静默空返回、无最终产出 | **100%**（610 tok） |
| 9 部件 | 塌缩（80k tokens） | **100%**（909 tok） |
| 12 部件 | **0/12**（116k–1.61M tokens） | **100%**（1,129 tok） |

保真曲线 15/15 全对（N=4–12，每档 3 次）——**同模型在单一上下文里算 12 行数字毫发无损，
放进多 agent 编排同规模直接崩盘且成本放大百倍**。因果隔离完成：塌缩源于编排/协调本身，
不是模型算力。

进一步用确定性管道（worker 算 → 返回文本经 spawn 通道 → lead 收口，零指令方差）定位：
**一道 spawn 边界的中继 100% 无损**（N=4–12 全绿，每链约 2.3k tokens）。塌缩只发生在
"多分身并行 + lead 汇总"的完整编排里。**塌缩的预测变量是汇总者要同时持有的并行产出数，
不是数据行数，也不是中继跳数。**

多 agent 的适用边界铁律：**单上下文能解决、或能串行分解的问题，拆成并行多 agent 只有代价。**

### 5. 共享黑板：指令是脆弱通道，结构保证才有效——而"动态阶段门控"才是正解

让成员"把结果写进共享黑板"这件事，三级递进的指令强制（成员描述 → lead 派工转述 →
role 系统注入）全部失效；唯一可靠的是**结构保证**——框架层在分身每轮结束时自动落盘
（桥监听 `round_completed` 事件），剥离模型裁量权。
但即便黑板正常工作：中继保真时（lead 派工文本带数据），共享比隔离多花 2–6 倍 token 且零收益。

**静态策略（全隔离 / 全共享）在 12 部件规模上全部失败（0/12）时，动态阶段门控恢复了满分**：
第一波 3 个核算员完全隔离并行 → 框架自动落盘 → 第二波汇总者获共享读权限交叉核对。
成本 51–55k tokens，是静态隔离（1.61M）的 1/30。
**隔离度不该是静态选择，而是按阶段动态切换：写时隔离（保多样、防污染），读时共享（保整合）。**

### 6. 成本可预测性是独立于质量的第一维度，且能被 role 注入校准

N=5 方差（四条件 × 5 场，质量全部满分）：单干 CV=0.04，混合 0.18，
隔离 **0.96**（lead 在单干与开 4 分身之间摇摆），全共享 **1.38**（双峰：3k vs 135k）。
**多 agent 的成本方差主要来自编排决策的随机性**；给成员写清楚协议的 role 提示
意外地稳住了 lead 的决策（mixed 最稳定）。预算敏感的任务用单干——质量一样，成本可预测。

### 7. 实用决策规则（当前数据支持）

- 明确、可验证、数据给定的任务 → **单开一个 agent**（省 3–12 倍）；
- 模糊、探索型、需要运行时调度 → 自由集群；
- 预算/工期敏感 → 避免多 agent（成本方差大一个数量级）；
- 共享状态只有在"中继会失败"（中间产物超上下文 / 弱模型中继）时才值得买。

## 附带产出的框架问题清单（给 aiteam-frame / pi SDK）

实验过程中实测到的 4 类静默失败，框架使用者一定会踩（完整 issue 草稿见 `jerphy_issues.md`）：
1. provider 限流 429 被 `prompt()` 吞成**零 token 空成功**（error=null）；
2. **分身级**静默失败（worker 0 token 返回无 error），宿主级用量检查看不见；
3. 上下文超限 = 永久静默空产出（审计已知）；
4. 指令优先级：lead 的派工文本会压倒成员的系统 role——协作协议必须走结构注入。

## 诚实声明

- 多数格子 N=1 或 N<5，方差数据仅 T4b 有 N≥3；单次结果不足以做统计断言。
- 成本数字为保守估算（官方价目，高峰口径）；订阅内消耗按 0 计。
- 部分结论跨 3 个模型厂家方向一致，但边界图尚未完成——**"固定流程在什么任务上必赢"目前没有找到反例格子**，
  这本身就是当前最大的未决问题。
