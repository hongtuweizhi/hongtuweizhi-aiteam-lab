# handoff-probe：交接保真探针

测量多 agent 管线"过一手交接丢多少信息"。核心方法：把 **K 条机器可核验的约束**
（专有名词、精确数字、可算的关系）埋进任务，逐阶段检查它们是否存活在产出里——
不依赖任何 LLM 判断。

模板：`scripts/probe_template.py`（内置 selftest 自证逻辑正确）。

## 使用流程

1. **设计 K 条约束**（K=5 左右最有效）。每条必须是**产出文本里的 token/数值**，能被
   正则或算式核验。好例子：
   - 场地名 + 时间窗数字（"云轩厅"、14:00–18:00）；
   - 预算上限与可算明细（8000 = 2000 + 48×58...）；
   - 折算关系（64 × 75% = 48）；
   - 专有名词（"林岚"）与下限（≥45 分钟）。
   坏例子： qualitative 要求（"风格专业"）——那需要盲评，不归本 skill。

2. **实例化模板**。复制 `scripts/probe_template.py`，改两处：
   - `[EDIT-1] CONSTRAINTS`：每条约束一个核验函数（输入某阶段产出文本 → bool）；
   - `[EDIT-2]` 被测系统的阶段产出如何采集（两种模式，见下）。

3. **两种采集模式**：
   - **fixed/链式管线**：每个 agent 的产出都能拿到（框架事件、日志、或每步落盘）→
     模板输出**逐跳存活曲线**：第几跳丢的、丢的是哪条。
   - **free/黑盒系统**：只能拿到终稿 → 输出**终局存活率**（K 条里活了几条）。
     隐蔽增强：把任务文本与产出文本做差集扫描，定位"丢失发生在派工还是执行"。

4. **读取结果**。模板输出：
   - `per_stage`：每跳的存活明细；
   - `first_lost_at_stage`：每条约束第一次丢失的跳数（定位责任跳）；
   - `survival_rate_final`：终局存活率（硬指标）。

## 铁律与注意

- 存活判据是"出现在产出里"，不是"agent 声称遵守了"——后者已被证明不可信；
- 核验函数用**逐字 token + 数值精确匹配**，避免同义宽容（要测的就是逐字保真）；
- 模型强弱会影响绝对值（弱模型丢得更多），但**同模型两条件对比**的机制结论不受影响；
- 固定流程的典型期望曲线：第一跳丢 40–60%，终稿 20–50%——本项目实测（5 条约束，
  第一跳丢 3 条，终稿剩 1 条，而同任务自由集群 100% 存活）。

## 自检

改完模板先跑 `python probe_template.py selftest`——内置 5 约束 3 阶段的合成数据，
验证曲线、首次丢失定位与终局存活率计算正确。
