# objective-scorer：客观判分器生成器

给任何"有标准答案的 agent 任务"装上机器判分。核心原则：**不信任自报**——
agent 声称完成了什么不算数，判分器只核对产出物本身。

模板：`scripts/checker_template.py`（内置 selftest 自证逻辑正确）。

## 使用流程

1. **判断任务可判性**。满足以下任一即可用本 skill：
   - 标准答案可由公式本地重算（成本、排程、路径、校验和…）；
   - 解空间小到可离线穷举（把精确最优写进判分器）；
   - 有固定数据文件，产出必须与数据一致（编造即错）。
   开放式主观任务不适用（那需要盲评 rubric，另做）。

2. **实例化模板**。复制 `scripts/checker_template.py`，改三处：
   - `[EDIT-1] INSTANCE`：钉死任务实例（数据写死在这里，任务文本与判分共用同一事实源，杜绝口径漂移）；
   - `[EDIT-2] ground_truth()`：本地重算标准答案（能穷举就穷举出精确最优）；
   - `[EDIT-3] FIELDS`：列出最终产出必须逐字段核对的项目（数值容忍 ±0.5 误差）。

3. **生成输出契约**（发给被测 agent 的最后要求）：
   "你的最后一条回复必须以一个 JSON 代码块结尾，形如 {…}，必须覆盖全部字段；
   JSON 之前可以先给分析过程。" 契约里**不要**出现"完成后声称达成 XX"——自报字段一律不要。

4. **接线**。对每份被测产出（result.json 的 finalText，或任何文本）：
   `python checker.py check <result.json>` → 得到逐字段判定 + violations 清单。
   崩溃/空产出必须单独标记（常见陷阱：provider 429 被吞成 0-token 空成功）。

5. **报告**。判分结果与自报对照着报：自报与客观的差值本身就是发现
   （本项目实测：自报达成 5 次被客观判分证伪）。

## 铁律

- 任务文本与判分器**共用同一份实例事实源**，防止口径漂移；
- 判分器不读 agent 的任何"我完成了"声明；
- 数值核对带小容差（浮点/千分位），字符串核对逐字；
- 空产出/无法解析 ≠ 0 分，要标为基建失败并单独归因。

## 自检

改完模板后先跑 `python checker.py selftest`——内置演示实例验证打分逻辑本身正确，
再接你的真实任务。
